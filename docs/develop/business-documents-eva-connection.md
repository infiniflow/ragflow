# Отдельное соединение EVA для раздела «Документы»

Дата: 2026-09-05.

## Настройка

В админке → «Документы» задаются адрес API EVA, адрес веб-интерфейса, пространство, проверка SSL и включение архивных объектов. Пространство можно указать по ID или выбрать по названию через «Загрузить пространства». Загрузка списка использует введённые настройки и общий токен, не сохраняет их.

Общий токен необязателен: интерактивное чтение использует его первым, при отсутствии — личный токен пользователя из профиля. Ошибка 401/403 общего токена не приводит к переключению на личный. Для записи в EVA всегда нужен личный токен и существующий процесс согласования/подготовки/публикации. Соединение появляется в профиле без создания источника данных.

Пустое поле токена при сохранении того же API сохраняет секрет. Флажок удаления очищает его. При смене API старый общий токен не переносится. «Отключить соединение» выключает EVA в «Документах» и не изменяет источники данных.

## Хранение и переход

- Новая запись `system_settings.business_documents.eva_connection` содержит конфигурацию и зашифрованный общий токен. Новые таблицы и миграции схемы не нужны.
- Секрет шифруется Fernet с отдельным контекстом ключа. Материал ключа: `RAGFLOW_CREDENTIALS_KEY` либо существующий secret key приложения. API формы возвращает только признак наличия токена.
- До первого сохранения поддерживается существующая запись `business_documents.eva_connector_id`: ранее выбранное соединение продолжает работать, а форма показывает его поля без секрета.
- Первое сохранение копирует настройки в самостоятельную запись. При совпадении API и пространства сохраняется ID, используемый привязками и изменениями документов. Запись коннектора не меняется и не создаётся.
- При смене API или пространства генерируется новый ID; старые привязки не могут обращаться к новому пространству без повторной привязки. Отключение хранит явную пустую конфигурацию и не включает старый источник обратно.
- Поля `connector_id` в сохранённых привязках, журнале изменений и профильном API сохранены как действующий контракт идентификации соединения.

Административные GET/PUT `/api/v1/admin/business-documents` работают с `eva_connection`; POST `/api/v1/admin/business-documents/eva-spaces` возвращает `items`. Все три маршрута требуют активного администратора. Профильные операции остаются ограничены текущим пользователем. Настройки имеют существующую системную область админки; права на сами документы остаются в их владельце сценария.
