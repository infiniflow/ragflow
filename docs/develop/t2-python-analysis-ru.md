# T2: первый наблюдательный анализ Python

Дата: 2026-09-06. Реализован `tools/quality/inspect_python.py`, версия 0.1.0. Это ограниченная подготовка T2 в режиме отчёта; T1 имеет открытые условия, весь T2 и блокирующий T3 ещё не приняты. Инструмент не импортирует приложение, не меняет исходники и не удаляет код.

## Запуск

Из корня репозитория:

```powershell
.venv/Scripts/python.exe -B tools/quality/inspect_python.py --module business-documents --output output/quality/python-business-documents.json
.venv/Scripts/python.exe -B -m pytest test/unit_test/tools/quality/test_inspect_python.py
ruff check tools/quality/inspect_python.py test/unit_test/tools/quality/test_inspect_python.py
ruff format --check tools/quality/inspect_python.py test/unit_test/tools/quality/test_inspect_python.py
```

Требуются Git, Python 3.13 и установленный PyYAML. Повторение `--module` добавляет точный ID владельца из `module-map.yaml`. До запуска новые собственные пути должны быть внесены в реестр. Нельзя направлять отчёт на исходник: внутри репозитория разрешён только игнорируемый путь, который не находится под Git-контролем.

Код выхода 0 означает, что запрошенные статические наблюдения собраны без обнаруженных пробелов. Это статус `OBSERVED`, **не PASS архитектуры**. Код 2 и `INCOMPLETE` означает динамическую/неразрешённую загрузку, ошибку разбора или входов. При ошибке входов новый отчёт не создаётся; старый файл по тому же пути нельзя принимать за результат неуспешной команды. `policy_status` всегда `NOT_EVALUATED`, `dead_code_status` — `NOT_ANALYZED`.

## Что анализируется

- Корневой Python API/worker профиль: `api`, `admin`, `agent`, `common`, `rag`, `deepdoc`. Выбор владельца относится к стартовым файлам; транзитивные зависимости включают неизменённый upstream. Код из дополнительных source roots (`services/*/src`, SDK), тесты, frontend и Go не объявляются проверенными.
- Обычные и относительные импорты, возможные submodules в `from`-импорте, неявная загрузка родительских `__init__.py`. Импорт символа не превращается автоматически в импорт одноимённого модуля.
- Импорты внутри функций и условных ветвей отмечены отдельно; обе ветви fallback сохраняются. Простой `typing.TYPE_CHECKING` и отложенные аннотации отделены от возможных runtime-зависимостей.
- Литеральные `importlib.import_module`/`__import__`, включая импортированные aliases. Вычисляемые/относительные динамические цели, конфликтующие aliases, передача import callable через присваивание, `exec`, file loaders, star imports и `__getattr__` оставляют явные пробелы.
- Кратчайшие наблюдаемые пути к ORM, web frameworks, известным сетевым клиентам и точным bootstrap-модулям. Это признаки связанности для ARC-01/02, а не готовый allowlist или доказательство выполнения I/O. Например, `pathlib` сам по себе не считается нарушением.
- Для функций выбранного владельца: точки ветвления, синтаксическая вложенность, вложенные циклы и число statements. Вложенные функции учитываются отдельно с квалифицированным именем; последовательные генераторы comprehension учитываются как вложенные обходы.

Пороги сигналов — 20 точек ветвления, 5 уровней вложенности, 2 вложенных обхода. Они служат для первичного разбора SIMP-01, не являются baseline или запретом. Это собственные AST-метрики версии 0.1.0, не подмена McCabe/Radon. Они не доказывают O(n²), время, объём памяти или лишний алгоритм. Перед упрощением нужны контракт, измерения и проверки по [протоколу](continuous-code-simplification-ru.md).

## Достоверность и ограничения

Отчёт содержит SHA инструмента и каждого прочитанного Python-файла, Python/OS, HEAD, проверенную upstream-базу и fingerprint актуального T0. Происхождение узлов берётся из свежего capture, а не из названия каталога. До завершения повторно сверяются исходные байты и provenance; конкурентная правка означает отказ. Это обнаружение изменений во время чтения, не блокировка рабочего дерева после возврата команды.

Граф консервативен: импорт внутри никогда не вызываемой функции всё равно является потенциальной зависимостью. `from package import name` может выбирать экспорт вместо submodule. Конфликт одноимённого файла и пакета отклоняется, а не разрешается догадкой. Scope-aware интерпретатор Python, произвольная reflection, import hooks и смена `sys.path` не реализованы; отсутствие диагностического сообщения не доказывает отсутствие этих механизмов. Сторонние библиотеки не выполняются и не обходятся транзитивно. Циклы с package initializers не объявляются нарушениями ARC-03.

Код не получает статус мёртвого из-за отсутствия входящих рёбер. Полный анализ достижимости, persisted DSL, whitelist patch, изолированный import test, проверки TypeScript/Go, строгая схема разрешённых рёбер и CI gate остаются следующими частями T2/T3. Пустой baseline и исключения не создавались.

## Проверки реализации

Изолированные фикстуры проверяют разрешение imports и symbols, родительский bootstrap без исполнения приложения, транзитивный helper → ORM, dynamic aliases и их затенение, аннотации, namespace packages, отсутствующие локальные модули, conditional/type-only/deferred imports, fallback, exports, синтаксические ошибки и регистрацию с циклом. Отдельные временные Git-репозитории проверяют настоящий CLI, ошибочный owner, подмену upstream tree, новый неучтённый файл, запрет перезаписи исходника и конкурентную правку.

Результаты запуска по рабочему проекту и проверки самого инструмента записываются отдельно от замороженного кандидата C. Прежние тесты C не переносятся автоматически на эту реализацию.
