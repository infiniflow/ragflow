Требуются Git, Python 3.13 и установленный PyYAML. Повторение `--module` добавляет точный ID владельца из `module-map.yaml`; `--boundary`, `--connection`, `--cycle-check` и `--runtime-probe` выбирают точные ID из `python-boundaries.yaml`; `--profile` выбирает точный DEAD-01 профиль из `python-dead-code.yaml`. Если selector не указан, соответствующий runner проверяет все настроенные записи. Необязательный `--base-ref` архитектурного runner фиксирует разрешённый SHA базы PR; без него локальный отчёт явно пишет `NOT_PROVIDED_LOCAL_REPORT`. До запуска новые собственные пути должны быть внесены в реестр. Нельзя направлять отчёт на исходник: внутри репозитория разрешён только игнорируемый путь, который не находится под Git-контролем.

Для `inspect_python.py` код выхода 0 означает `OBSERVED`, **не PASS архитектуры**; код 2 и `INCOMPLETE` означает динамическую/неразрешённую загрузку, ошибку разбора или входов. Его `policy_status` всегда `NOT_EVALUATED`, `dead_code_status` — `NOT_ANALYZED`. Для `check_python_dead_code.py` код 0 также означает только завершённое статическое наблюдение; `policy_status=NOT_EVALUATED`, `dead_code_status=NOT_CONFIRMED`, а код 2 запрещает принимать неполный результат. Кандидат не является разрешением на удаление, режима `apply` нет. Для `check_architecture.py`: 0 — настроенные статические и runtime-проверки завершились без находок; 1 — есть доказанная запрещённая зависимость, новый/лишний symbol, устаревшее разрешение, неверный runtime export/route или запрещённый import-time effect (`FAIL`); 2 — граф, конфигурация или выполнение пробы неполны (`INCOMPLETE`). `PASS` относится только к указанным правилам и scope. При ошибке входов новый отчёт не создаётся; старый файл по тому же пути нельзя принимать за результат неуспешной команды.

## Что анализируется

- Корневой Python API/worker профиль: `api`, `admin`, `agent`, `business_documents`, `common`, `rag`, `deepdoc`. Выбор владельца относится к стартовым файлам; транзитивные зависимости включают неизменённый upstream. Профиль `asr-service` явно сопоставляет `services/asr-online-service/src` с import root, запускает runtime-пробы через первый существующий интерпретатор из платформенных кандидатов `.venv/Scripts/python.exe` и `.venv/bin/python`; отсутствие обоих даёт `INCOMPLETE`. Профиль `web` здесь используется для exact contracts routes/navigation, bootstrap/provider/router composition и service factories. Широкий TypeScript-граф выполняется отдельным observer и имеет собственные [границы достоверности](t2-typescript-analysis-ru.md); SDK и другие runtime roots им не объявляются проверенными.
- Обычные и относительные импорты, исходные имена symbols независимо от локальных aliases, возможные submodules в `from`-импорте, неявная загрузка родительских `__init__.py`. Symbols дочернего импорта не приписываются parent initializer; импорт символа не превращается автоматически в импорт одноимённого модуля.
- Для каждого выбранного модуля — прямые потенциальные static consumers с путём, import kind, symbols, origin и owner потребителя. Type-only imports исключаются из runtime consumer inventory; parent initializer edges остаются видимыми. Это обратный индекс импортов, не call graph и не доказательство достижимости от process entrypoint.
- Импорты внутри функций и условных ветвей отмечены отдельно; обе ветви fallback сохраняются. Простой `typing.TYPE_CHECKING` и отложенные аннотации отделены от возможных runtime-зависимостей.
- Литеральные `importlib.import_module`/`__import__`, включая импортированные aliases. Вычисляемые/относительные динамические цели, конфликтующие aliases, передача import callable через присваивание, `exec`, file loaders, star imports и `__getattr__` оставляют явные пробелы.
- Кратчайшие наблюдаемые пути к ORM, web frameworks, известным сетевым клиентам и точным bootstrap-модулям. Это признаки связанности для ARC-01/02, а не готовый allowlist или доказательство выполнения I/O. Например, `pathlib` сам по себе не считается нарушением.
- Для функций выбранного владельца: точки ветвления, синтаксическая вложенность, вложенные циклы и число statements. Вложенные функции учитываются отдельно с квалифицированным именем; последовательные генераторы comprehension учитываются как вложенные обходы.
- Изолированный ARC-01 import probe проверяет точные пути и exports, загруженные локальные модули, отсутствие настроенных bootstrap/ORM/framework prefixes, stdout/stderr, новых non-daemon threads и запрещённых socket/process audit events.
- Изолированный ARC-02 registration probe исполняет реальный файл HTTP entrypoint через тот же file-loader/Blueprint контракт и сверяет точный набор route/method/endpoint. Инфраструктурный `api.apps` и семь импортируемых сервисных модулей заменяются узкими stubs с перечисленными symbols; вызовы обработчиков не выполняются.
- ARC-02 `pytest_contract` запускает только перечисленные точные pytest nodes и разбирает временный JUnit-отчёт. Автозагрузка сторонних pytest plugins отключена для воспроизводимого завершения; явно загружается только требуемый текущим `pyproject.toml` модуль `pytest_asyncio.plugin`. Assertion failure даёт `FAIL`; error, skip, timeout, отсутствие отчёта или несовпадение ожидаемого числа тестов дают `INCOMPLETE`. Путь теста должен принадлежать владельцу в свежем T0, а его SHA включается в отчёт даже вне source roots статического профиля.
- Ограниченная ARC-03 проверка строит strongly connected components по явным runtime imports внутри `business_documents/**` и полного ASR source package. Type-only и неявные parent-initialization edges не создают cycle finding; вычисляемая динамика или ошибка разбора дают `INCOMPLETE`, а найденный явный собственный цикл — `FAIL`.
- DEAD-01 scanner рассматривает верхнеуровневые функции и классы явно настроенных owned-профилей `business_documents/**` и ASR source package. Точные статические imports, ссылки уровня модуля, decorators/defaults/bases и локальная достижимость ведут к `PRESERVE`; публичная или доступная через module import поверхность без точного потребителя требует `REVIEW_REQUIRED`; приватная статически недостижимая группа остаётся `STATIC_CANDIDATE`, но не dead-code verdict. Для каждого symbol записывается fingerprint без номера строки.

Пороги сигналов — 20 точек ветвления, 5 уровней вложенности, 2 вложенных обхода. Они служат для первичного разбора SIMP-01, не являются baseline или запретом. Это собственные AST-метрики `inspect_python.py`, не подмена McCabe/Radon. Они не доказывают O(n²), время, объём памяти или лишний алгоритм. Перед упрощением нужны контракт, измерения и проверки по [протоколу](continuous-code-simplification-ru.md).

## Достоверность и ограничения

Отчёт содержит SHA инструмента и каждого прочитанного Python-файла, Python/OS, HEAD, проверенную upstream-базу и fingerprint актуального T0. Происхождение узлов берётся из свежего capture, а не из названия каталога. До завершения повторно сверяются исходные байты и provenance; конкурентная правка означает отказ. Это обнаружение изменений во время чтения, не блокировка рабочего дерева после возврата команды.

Граф консервативен: импорт внутри никогда не вызываемой функции всё равно является потенциальной зависимостью. `from package import name` может выбирать экспорт вместо submodule. Конфликт одноимённого файла и пакета отклоняется, а не разрешается догадкой. Scope-aware интерпретатор Python, произвольная reflection, import hooks и смена `sys.path` не реализованы; отсутствие диагностического сообщения не доказывает отсутствие этих механизмов. Сторонние библиотеки не выполняются и не обходятся транзитивно. Циклы с package initializers не объявляются нарушениями ARC-03; широкая проверка циклов остальных owned packages ещё не включена.

Код не получает статус мёртвого из-за отсутствия входящих рёбер: `reverse_imports` и `STATIC_CANDIDATE` — только данные для разбора потребителей и динамических пробелов. `python-dead-code.yaml` содержит чистый domain-профиль и полный source-пакет ASR, но не доказывает reflection, persisted DSL, внешние SDK/API, assets или runtime coverage. `python-boundaries.yaml` задаёт scope и запрещённые категории ARC-01, точные source/target/symbol для статической части ARC-02, два ограниченных ARC-03 cycle scope, изолированные импорты Business Documents/ASR, две Quart registrations и пятнадцать exact pytest contracts, включая полные inventories FastAPI ASR и всех 15 локально изменённых/добавленных REST API loaders, Python API/Flask admin bootstraps, task-executor runtime root, Business Documents worker lifecycle, ASR lifespan/thread pool и sync worker process/connector dispatch registry; `integration_dependencies` T0 не стали разрешёнными импортами. Module-level доступ разрешается только явным маркером `<module>`, wildcard запрещён. Вычисляемая обратная загрузка вне перечисленных integration sources остаётся ручным условием. Runtime worker блокирует настроенные Python audit events, но не является OS sandbox. Registration probes доказывают импорт и регистрацию указанного HTTP surface, но не auth/tenant-поведение или выполнение handler. Agent contracts используют реальные registries и Canvas loader, проверяя OpenMetadata и Retrieval вместе с round-trip generated saved DSL. Adapter contract проверяет передачу tenant/prompt/payload/retry/token limit и actor/request/result двумя Business Documents production adapters без реальных LLM/search calls. Bootstrap contracts исполняют реальные `api/ragflow_server.py` и `admin/server/admin_server.py` как `__main__` со stub-границами; task-executor contract загружает реальный модуль и закрепляет registries/CLI, `TE_RUN_MODE`, unacked-before-live selection, special fan-out hydration с восстановлением DB task и message context, acknowledgement non-runnable messages, empty/error poll behavior, cancellation/failure accounting, trace/progress reporting, special-task operation log с referent до ack, один полный heartbeat/report/expired-worker cleanup cycle, cleanup/ack, limiter release и shutdown cancellation. API progress loop, реальные queue operations, DB/Redis/network и HTTP handlers не выполняются: соответствующие task-executor контракты используют детерминированные doubles и не доказывают доступность инфраструктуры. ASR lifecycle contract использует реальный context manager и класс `Worker` с doubles потоков, но не запускает inference; он проверяет health-before-start, обязательный stop в `finally`, идемпотентный повторный start при живых потоках и join до 30 секунд. Business Documents worker contract закрепляет один daemon thread, poll interval и wake signal; sync worker contract — точное соответствие 37 внешних `FileSource` handler-классам, consumer identity, logger/async handoff, settings, signal wiring и один dispatch-loop проход. Frontend contract разбирает реальные `web/src/routes.tsx`, `web/src/constants/navigation.ts`, `web/src/main.tsx`, `web/src/app.tsx` и `web/src/utils/register-server.ts` установленным TypeScript parser. Он проверяет восемь локально затронутых lazy targets, существование их модулей, два публичных navigation paths, telemetry-before-language bootstrap, единственный React root, provider/router composition, восстановление сохранённого языка и фактическое поведение legacy/next HTTP service factories, включая отсечение унаследованных записей. Отсутствие Node/parser даёт `INCOMPLETE`, а несовпадение контракта — `FAIL`. Широкие TypeScript и Go graphs вынесены в отдельные observers: они не дают policy/dead-code verdict. Их текущие entrypoints, cycles, owned unreachable paths, dynamic gaps и directives классифицированы отдельным report-only tool. Анализ неохваченных adapters/surfaces, исторический persisted DSL, whitelist patch/apply и итоговый runtime/dead-code verdict остаются manual/future work; selector, aggregate job и CI gate относятся к T3. Пустой baseline и исключения не создавались.

## Проверки реализации

Изолированные фикстуры проверяют разрешение imports и symbols, родительский bootstrap, прямой и транзитивный helper → ORM/core, допустимый чистый domain рядом с отдельным adapter, точные forward/reverse symbols, новый consumer, лишний symbol, устаревшее разрешение, явный module access без wildcard, dynamic aliases и их затенение, аннотации, namespace packages, отсутствующие локальные модули, conditional/type-only/deferred imports, fallback, exports, синтаксические ошибки, явный owned cycle и исключение parent-init edges. Явный import root проверен на вложенном `services/example-service/src` с дефисом вне Python package path. DEAD-01 fixtures проверяют точный статический consumer, приватный кандидат и взаимно достижимую только изнутри группу, public/`__all__`/type-only/star contracts, неизвестную динамику, стабильный fingerprint и запрет path traversal. Runtime-фикстуры в новых процессах проверяют чистый import из корня и вложенного `src`, фактическую загрузку запрещённого parent dependency, блокировку socket effect, ошибку импорта без ложного PASS, точный Quart route inventory и отказ для лишнего/пропавшего route либо устаревшего stub symbol. Pytest-contract fixture различает pass, assertion failure и skip, поддерживает отдельный рабочий каталог/`PYTHONPATH`; отсутствие профильного интерпретатора отдельно подтверждено как `INCOMPLETE`.
