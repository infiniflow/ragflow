# Build RAGFlow Docker Image

Build the Go backend and web frontend into a local Docker image for development and testing. The image uses external LLM and embedding services at runtime.

## Prerequisites

- CPU &ge; 4 cores
- RAM &ge; 16 GB
- Disk &ge; 50 GB
- Docker &ge; 24.0.0 with Docker Compose &ge; v2.26.1 and BuildKit
- Access to the `infiniflow/ragflow_deps:latest` and `infiniflow/github_action_runner:latest` images during the build

The Go image currently targets `linux/amd64`. On an Apple Silicon Mac, Docker Desktop builds and runs this image through x86-64 emulation. A native `linux/arm64` build is not supported by the checked-in Go Dockerfile and its native dependencies.

## Platform support

- **Linux x86-64:** CPU deployment is the default and recommended path. A GPU Compose deployment is available when the host has NVIDIA Container Toolkit configured. In the RAGFlow open-source 1.0 release, the Go DeepDoc backend remains CPU-only and does not support GPU inference.
- **Apple Silicon macOS:** Build and run the `linux/amd64` image through Docker Desktop x86-64 emulation. Document processing and image builds may be slower than on an x86-64 Linux host.
- **Linux ARM64:** Native builds are not supported by the checked-in Go Dockerfile and its native dependencies. Do not use an x86-64 image on ARM64 unless the resulting emulation setup has been validated for your workload.
- **Document engines:** Elasticsearch is the default engine in the Compose example. Infinity and other supported engines may have different CPU, GPU, and architecture requirements; verify the selected engine before deployment.

Before starting the stack, make sure the host ports used by the selected Compose profile are available. At minimum, check the web, metadata database, cache, object storage, and NATS monitoring ports. If a port is already in use, change the corresponding value in `docker/.env-go` and `docker/.env` together where both files define the same dependency.

## Build the Go image

Run the build from the repository root. Keep the `.git` directory in the build context: `Dockerfile_go` uses it to stamp the image version.

```bash
git clone https://github.com/infiniflow/ragflow.git
cd ragflow
docker build --platform linux/amd64 -f Dockerfile_go -t ragflow:go-local .
```

`Dockerfile_go` builds the Go server and web frontend. `infiniflow/ragflow_deps:latest` supplies document models and tokenizer assets; `infiniflow/github_action_runner:latest` supplies the build toolchain and prebuilt ONNX Runtime libraries. You do not need to build either dependency image separately for this command.

## Start the service

For the default Elasticsearch document engine on Linux, set `vm.max_map_count` to at least 262144 on the Docker host. For macOS, use the Docker Desktop command below instead.

```bash
sudo sysctl -w vm.max_map_count=262144
```

Set `RAGFLOW_IMAGE=ragflow:go-local` in `docker/.env-go`. That file also controls the document engine, CPU or GPU selection, ports, and dependency credentials. Change the default passwords before making the service accessible over a network.

```bash
cd docker
docker compose --env-file .env-go -f docker-compose-go.yml up -d
```

The default `DEVICE=cpu` starts `ragflow-cpu`. To use `ragflow-gpu`, set `DEVICE=gpu` in `.env-go` and configure the NVIDIA container runtime on the host. This selection can make GPUs available to components that explicitly support them, but it does not enable GPU execution for the open-source 1.0 Go DeepDoc backend.

## Verify the service

```bash
docker compose --env-file .env-go -f docker-compose-go.yml ps
docker compose --env-file .env-go -f docker-compose-go.yml logs --tail 50 ragflow-cpu
curl -f http://localhost/api/v1/system/healthz
```

Use `ragflow-gpu` in the logs command if you selected GPU. A healthy API returns HTTP 200. If you changed `SVR_WEB_HTTP_PORT` in `.env-go`, use that port in the health-check URL and when opening the web interface in a browser.

For a development checkout, a database version error may require `RAGFLOW_DEV_MODE=true` in `.env-go`. Use this only for local development; keep it `false` for production.

## macOS with Docker Desktop

The same Go image and Compose file work on macOS. On Apple Silicon, keep `--platform linux/amd64` in the build command so that the x86-64 Go image and native libraries use the same architecture. Emulation can make the build and document processing slower than on an x86-64 Linux host.

1. Start Docker Desktop and build from the repository root:

   ```bash
   git clone https://github.com/infiniflow/ragflow.git
   cd ragflow
   docker build --platform linux/amd64 -f Dockerfile_go -t ragflow:go-local .
   ```

2. If you use the default Elasticsearch document engine, set `vm.max_map_count` inside Docker Desktop's Linux virtual machine:

   ```bash
   docker run --rm --privileged alpine sysctl -w vm.max_map_count=262144
   ```

   Repeat this command after restarting Docker Desktop. It is unnecessary when using another document engine such as Infinity.

3. Set `RAGFLOW_IMAGE=ragflow:go-local` in `docker/.env-go`, then start the Go stack:

   ```bash
   cd docker
   docker compose --env-file .env-go -f docker-compose-go.yml up -d
   curl -f http://localhost/api/v1/system/healthz
   ```

   Wait for the health check to return HTTP 200, then open `http://localhost` in a browser. Include `SVR_WEB_HTTP_PORT` in both URLs if you changed its default value. The older `docker-compose-macos.yml` builds the non-Go `Dockerfile`; use `docker-compose-go.yml` for this image.
