RAGFlow is an open-source RAG (Retrieval-Augmented Generation) engine based on deep document understanding. When integrated with LLMs, it is capable of providing truthful question-answering capabilities, backed by well-founded citations from various complex formatted data.

This guide takes you from deploying RAGFlow with Docker Compose to asking your first question about your documents. After deployment, follow the 10-minute tutorial to configure models, create a Dataset, upload a document, and start a Chat.

If RAGFlow is already running, go directly to the [10-Minute Tutorial](#10-minute-tutorial).

## Prerequisites

- A recommended starting configuration of 4 CPU cores (x86-64 or ARM64), 16 GB RAM, and 50 GB free disk space. Actual requirements depend on the document engine, data volume, parsing workload, and concurrency. Local models and OceanBase require additional resources.
- Docker &ge; 24.0.0 with Docker Compose &ge; v2.26.1 and BuildKit;
- Access to the dependency image `infiniflow/ragflow_deps:latest` during the image build, and to an LLM and embedding model at runtime.

If Docker is not installed, see [Install Docker Engine](https://docs.docker.com/engine/install/).

## Start Up the Server {#start-up-the-server}

:::note
This guide deploys RAGFlow using Docker images and the Docker Compose configuration provided in the repository. Docker images are available for Linux x86-64 and ARM64 starting with v1.0.0. Docker automatically selects the image matching your host architecture when you use the release tag.
:::

1. For the default Elasticsearch document engine, ensure `vm.max_map_count` is at least 262144 on the Docker host:

   ```bash
   sysctl vm.max_map_count
   sudo sysctl -w vm.max_map_count=262144
   ```

   The change made with `sysctl -w` is temporary. To keep it after a reboot, set `vm.max_map_count=262144` in `/etc/sysctl.conf`. On Docker Desktop, apply the setting to its Linux VM.

2. Clone the repository:

   ```bash
   git clone https://github.com/infiniflow/ragflow.git
   ```

3. Check out the release tag and start the prebuilt RAGFlow Docker image with Docker Compose:

   ```bash
   # Enter the Docker deployment directory.
   cd ragflow/docker
   # Check out the latest release tag; replace it with another version if needed.
   git checkout v1.0.0
   # Start the RAGFlow services and their dependencies in the background.
   docker compose -f docker-compose.yml up -d
   ```

   To deploy another version, replace `v1.0.0` with a tag from the [Releases](https://github.com/infiniflow/ragflow/releases) page. Before starting the services, ensure `RAGFLOW_IMAGE` in `docker/.env` uses the matching image tag.

   The `docker/.env` file controls `DOC_ENGINE`, service ports, and dependency credentials. Change the default passwords before deploying to a network-accessible host.

   In the RAGFlow open-source 1.0 release, DeepDoc layout analysis, OCR, and table recognition use CPU inference.

   :::caution Development checkouts
   A development checkout can report a code version older than the database migration version, including immediately after its own migrations. In that case, the RAGFlow server refuses to start with `Refusing to start: database was migrated by a newer version`. For local development with this checkout, set `RAGFLOW_DEV_MODE=true` in `.env` and run the Compose command again. This disables the database downgrade check; leave `RAGFLOW_DEV_MODE=false` for production, and use a binary whose version is at least the database migration version.
   :::

4. Check that the service is running:

   ```bash
   docker ps
   docker logs -f ragflow-cpu
   ```

   After initialization, check the RAGFlow API and its dependencies through the web port from another terminal:

   ```bash
   curl -f http://localhost/api/v1/system/healthz
   ```

   A successful response has HTTP status 200. If you changed `SVR_WEB_HTTP_PORT` in `.env`, include that port in the URL. Wait for this check to pass before opening the web interface.

5. Open `http://IP_OF_YOUR_MACHINE` in a browser and log in. If you changed `SVR_WEB_HTTP_PORT` in `.env`, include that port in the URL. For first-time access, register an account if registration is available, or use an account provided by your administrator.

The RAGFlow container runs the API server, ingestion workers, and data synchronization. Its startup script runs the database migrations before starting the services.

## 10-Minute Tutorial

Create a Dataset, upload a document, and use Chat to ask questions about its content. By the end of this tutorial, you will have a Chat that answers questions with references to your document.

Configure models → Create a Dataset → Upload a document → Start chatting

Before you begin, log in to RAGFlow and prepare:

- Access to a Chat model and an Embedding model, including any credentials required by your model provider.
- A small TXT, Markdown, or text-based PDF document containing information you want to ask about.

Document parsing and response times depend on the file size, model, and available resources.

### Configure Models {#configure-llms}

The **Chat model** generates answers. The **Embedding model** makes document content searchable. If both models are already available in your account, skip to [Create Your First Dataset](#create-your-first-dataset). Otherwise, configure them as follows:

1. Open **User settings** from your avatar, then select **Model providers**.
2. Under **Available models**, select your provider and create a provider instance.
3. Enter the required connection details, such as **API Key** and **Base URL**.
4. Add or select the Chat and Embedding models you will use, verify them, and save the instance.
5. Under **Set default models**, select your Chat model and Embedding model.

If your Chat and Embedding models use different providers, configure an instance for each provider.

For provider-specific instructions, see [Configure Model Providers](./guides/models/llm_api_key_setup.md). For locally hosted models, see [Deploy Local Models](./guides/models/deploy_local_llm.mdx).

### Create Your First Dataset {#create-your-first-dataset}

A Dataset holds the documents your Chat will search when answering questions.

1. Select **Dataset** in the navigation bar, then click **Create dataset**.

   <img src="https://raw.githubusercontent.com/infiniflow/ragflow-docs/main/images/create_dataset_2.jpg" alt="Open the Dataset page and create a Dataset" width="100%" />

2. Enter a **Name**, such as `My first Dataset`.
3. Select the **Embedding model** configured above.
4. In **Parsing mode**, select **General** and click **Save**.

Your new Dataset opens. Keep the default configuration for this tutorial and use the **Files** page to add your document.

Choose your Embedding model before parsing documents. For other parsing methods and model changes, see [Dataset Configuration](./guides/dataset/configuration.md).

### Upload and Parse a Document

Parsing converts your document into smaller sections, called chunks, that RAGFlow can retrieve when answering a question.

1. On the Dataset's **Files** page, click **Add file > Upload file**.
2. Select your document, enable **Parse on creation**, and click **Save**.

   <img src="https://raw.githubusercontent.com/infiniflow/ragflow-docs/main/images/upload_local_document.jpg" alt="Upload a document, enable Parse on creation, and save" width="600" />

3. Wait for parsing to complete. If you uploaded without enabling **Parse on creation**, select the document and click **Run** to start parsing.
4. Check that parsing completed successfully and the document has chunks before continuing.

If parsing fails, open the document's **Logs** to view the error. See [Dataset Document Management](./guides/dataset/files_dataset_document_management.md) for parsing and troubleshooting instructions.

### Create a Chat and Ask a Question {#set-up-an-ai-chat}

1. Select **Chat** in the navigation bar and click **Create chat**.
2. Enter a name, such as `My first Chat`, and confirm creation.
3. Click the gear icon to open **Chat setting**. In **Model**, select your Chat model. In **Datasets**, select the Dataset you just prepared.

   <img src="https://raw.githubusercontent.com/infiniflow/ragflow-docs/main/images/configure_chat.jpg" alt="Select the Chat model and the prepared Dataset in Chat setting" width="600" />

4. Expand **Advanced settings** and enable **Show citations**. Keep the other settings at their defaults and click **Save**.
5. In the chat window, select **Naive** beside the message box and ask a question whose answer is in your document.
6. Read the answer and open its citations to check the supporting document content.

Check that the answer contains information from your document and that opening a citation shows the supporting source content. You can then continue asking questions about the same document.

For additional settings, see [Chat Configuration](./guides/chat/chat_configuration.md).

### Optional: Check Retrieval Results {#intervene-with-file-parsing}

Use this optional check to inspect the document content or investigate answers that do not match your expectations.

1. Click the parsed document's name to view its chunks. Check that the text you expect is present and readable.

   <img src="https://raw.githubusercontent.com/infiniflow/ragflow-docs/main/images/file_chunks.jpg" alt="View the document chunks" width="100%" />

2. Return to the Dataset and open **Retrieval testing**.
3. Enter a question whose answer is in the document in **Test text**, then run the test.
4. Check that the results contain content that answers your question.

### If You Need Help

- **A model is not available for selection**: Check that it has been added and verified under **User settings > Model providers**. See [Configure Model Providers](./guides/models/llm_api_key_setup.md#verify-models).
- **Document parsing fails**: Open the document's **Logs** to view the error, then follow [View Parsing Status](./guides/dataset/files_dataset_document_management.md#view-parsing-status).
- **The answer has no citations**: Check that **Show citations** is enabled and that your Dataset contains parsed, enabled documents. Use [Retrieval testing](#intervene-with-file-parsing) to check whether your question finds supporting content.
