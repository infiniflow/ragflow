Fixes #19569 (defects #1 and #5 from the report).

## Problem

In-place MySQL upgrade v0.26.4 → v0.27.2 fails inside `ModelTypeMergeStage` because the driver returns `model_type` as `str` (the column is still `varchar` — this very stage converts it to an integer bitmask), and `if model_type & type_bit:` then raises `TypeError: unsupported operand type(s) for &: 'str' and 'int'`. The stage aborts, `--mark-database-version-on-success` never records the target version, every restart retries and fails again, and the container startup log only prints a `skipping all stages` line.

A second surface is `api.utils.model_utils.get_model_type_human`, which applies the same `&` to a row from `tenant_model.model_type`. When one row in a tenant's model list is still varchar (left over from a partial prior upgrade), `GET /api/v1/models` raises 500 for the entire list, emptying the *Default model* dropdowns across Settings / Chat / Agent.

## Fix

Two narrow changes; defects #2, #3 and #4 from the report (loud-fail exit, provider-instance in lookup key, existence-check in `check()`) are intentionally out of scope here — see *Future work* below.

### 1. `tools/scripts/mysql_migration.py` — `TenantModelIdMigrationStage._build_model_lookup`

Coerce `model_type` with `int()` and skip rows whose value cannot be parsed (with a warning). The migration stage now completes on databases that contain legacy varchar rows, records the target version, and stops retrying on restart.

### 2. `api/utils/model_utils.py` — `get_model_type_human`

Return `[]` for non-`int` (or `bool`) input. The endpoint still serves every other row in the model list while operators repair the offending row manually.

## Tests

`test/unit_test/api/utils/test_model_utils.py` gains four cases pinning the str / None / bool / int paths of `get_model_type_human`. The int happy-path assertion documents the canonical `ModelTypeBinary` bitmask ordering. Local run:

```
$ pytest test/unit_test/api/utils/test_model_utils.py -v
============================= 7 passed in 0.02s ==============================
```

A regression test for `_build_model_lookup` itself requires a MySQL fixture or a peewee mock; the inline fix is small enough that inspection plus the model_utils tests cover the mechanism.

## Future work (defects #2 / #3 / #4 from #19569, intentionally out of scope)

- **#2 (loud-fail):** exit non-zero and surface the error instead of absorbing it into `skipping all stages`, so startup logs and `--check-database-version` agree.
- **#3 (provider instance):** include the provider instance column in the SELECT and the lookup key, so two providers with the same `pure_name` (`Tongyi-Qianwen@default` vs `Tongyi-Qianwen@bailian`) cannot be cross-wired.
- **#4 (`check()` validity):** verify the referenced ids still exist in `tenant_model`, not merely that they look like a 32-char UUID, so regenerated ids do not leave dangling references.

Happy to follow up with one or more of these in a separate PR once the maintainers agree on the desired exit behavior (defect #2 changes operator-visible script semantics).
